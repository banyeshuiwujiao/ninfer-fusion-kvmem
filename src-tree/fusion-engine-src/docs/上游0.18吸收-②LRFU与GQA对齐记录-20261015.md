## LRFU 默认开关：保持关闭（分歧保留）

硬证据（e11b953 提交 message 的 A/B）：pool 53248、258k ctx、33 needles，
**old-binary / new-off / new-on 三组 33/33 recall 完全一致，token 总量 bit-equal** ——
即在我方架构上 LRFU-on 是**中性**（无收益、无回退）。上游默认开启发生在其自身架构与
启动配方上，不构成对我方的收益证据；保守起见默认保持 OFF，
`NINFER_TERNARY_KVMEM_SCORE_LRFU=1` 仍是可用的实验开关。

## GQA 聚合 max：env 门控选项（本次落地）

- 上游语义（`mean_key_retrieval.hpp` 注释）：Mean = 组内平均；**Max = 组内逐 Q 头取最大，
  再对 KV 头与参与层取平均**。两者都是选择数学（selection math），不改 payload/frontier/residency。
- 我方实现：`kvmem_retrieve_launch.cu` Phase 2 增加 `agg_max` 分支 —— 组内 `max(mass_qh)`，
  权重 `head_w × group`（= 1/(L×n_kv_heads)，等价于对 KV 头与层取平均）；
  mean 分支逐位保留原 Eq.10 算术。
- 开关：`NINFER_KVMEM_SCORE_AGG=max`（默认 mean；**默认路径逐位等价**，读一次 env 静态缓存，不在解码热路径）。
- 状态：编译通过、host 测试不受影响；**max 分支的 needle A/B 待做**（需重启生效）。

## sink/recent：不对齐（分歧落档）

上游 12288/1024 是其 **Windows 启动配方**（262144 全上下文、RTX 5060 Ti 16G 实测平台）。
我方引擎的选择预算是 229376（= 0.875×262144，给单轮生成留 32768），sink 走
`qw3::resolve_kvmem_keep_allocation` 公式而非抄显式覆盖值 —— 这是移植时刻意防
"误抄官方命令行显式值" 的设计（见 `kvmem_port_bridge.h:118-122` 注释）。
两套架构的 budget 语义不同，直接搬数字无依据。若未来要动 sink/recent，
必须走独立的 needle A/B，而不是版本对齐。
